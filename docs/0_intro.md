# ВСТУП

## Актуальність теми
Сучасні системи автомобільної діагностики функціонують в умовах жорстких вимог до затримки обробки телеметричних даних (Latency), надійності передачі даних через бездротові канали (Bluetooth) та відмовостійкості при пікових навантаженнях. Існуючі монолітні рішення (VCDS, TechStream, Delphi) не забезпечують асинхронної взаємодії між клієнтом, сервером та зовнішніми сервісами, що призводить до блокування запитів, втрат діагностичних даних та неможливості горизонтального масштабування. Відсутність контуру Observability унеможливлює виявлення деградації продуктивності, а синхронна обробка DTC-кодів створює ризик порушення цілісності даних при паралельних запитах.

## Об'єкт дослідження
Процес збору, передачі, асинхронної обробки та збереження діагностичних даних автомобіля в розподіленій клієнт-серверній системі.

## Предмет дослідження
Методи, архітектурні патерни (Event-Driven Architecture, CQRS, Saga) та технологічний стек (Flutter, FastAPI, Apache Kafka, PostgreSQL, Docker, OpenTelemetry) для забезпечення відмовостійкості, низької затримки та спостережуваності розподіленої системи автомобільної діагностики.

## Мета роботи
Розробка подієво-керованої екосистеми AutoSpark Pro для діагностики та обслуговування автомобілів на основі розподіленої архітектури з асинхронною обробкою даних, що забезпечує зменшення затримки відгуку, підвищення відмовостійкості та впровадження контуру спостережуваності для оперативного виявлення деградацій.

## Завдання проєкту
1. Проаналізувати існуючі аналоги (VCDS, TechStream, Delphi) та обґрунтувати вимоги до архітектури.
2. Обґрунтувати вибір технологічного стеку та архітектурних патернів (EDA, CQRS, Saga).
3. Спроєктувати архітектуру системи за допомогою UML-діаграм та C4-моделі.
4. Розробити алгоритми асинхронної обробки DTC-кодів із використанням Apache Kafka.
5. Спроєктувати інтерфейсну частину (Flutter-застосунок та Telegram-бот) та схему розгортання в Docker.
6. Провести інструментальний аудит коду через модульне та навантажувальне тестування (pytest, k6).
7. Дослідити ефективність запропонованої архітектури та підготувати науково-практичну публікацію.
